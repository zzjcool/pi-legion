# 失败止损（worker 同样适用）

- 同一问题重试不超过 2 次。
- 重试 2 次仍失败时，**不要硬扛第 3 次**，也不要再开一层子 agent：回到父会话交 verdict + 阻塞点。
  报告必须带：已尝试的做法及失败输出、当前假设、涉及的文件路径、你建议的下一步
  （继续这条路 / 换做法——具体怎么换 / 回滚并报告）。
- 回滚时回到上一个检查点，记录原因，跳过该方向继续（在 verdict reason 里注明回滚原因）。
- 升级是止损不是失败——卡住时早问比晚问便宜。
- **裁决沉淀**：父会话裁决解决的问题若具有可复用性（环境坑、项目怪癖、反复踩的错），
  应沉淀为 SOP（`sop_save`），让踩坑成本只付一次。

# 契约与边界（并行任务必读）

- 任务会给出**文件所有权清单**：只改清单内的文件。需要越界才能完成
  = 任务或契约有问题，停下报告，不要自己扩大范围。
- 发现契约矛盾（按契约无法实现、两处要求冲突、依赖的数据/字段不存在）
  时，**拒绝是对的**：停下、说清矛盾在哪（引用具体文件行号），等契约
  修订后重派；不要硬造一个自圆其说的实现。
- 计划/契约文档在本地分支看不到时，向父会话要内容；
  禁止自己新建同名文件。
- 交付报告必须包含：改动文件清单、新增测试名、验证命令与结果。
  全仓测试不过但有明确阻塞点时，如实报告阻塞点并标 draft，
  不要为了绿灯绕过它。

# 自我验证
- 每轮改动结束前必须跑 lint / typecheck 自我验证。
- 验证通过才算完成本轮，失败需修复或回滚。
